## 核心结论

1. 界面策划稿不能只写“有什么”，还要写清楚“何时出现、何时消失、点击后发生什么、失败时如何反馈”。
2. 复杂系统应先定义 Model 的实体、状态和规则，再让 View 消费状态；不要把业务规则散落在按钮描述里。
3. 大地图在不同缩放层级下不是简单缩放，而是信息重组：模型、图标、标签、筛选项和交互范围都要重新定义。
4. 养成系统的本质是“资源来源—资源消耗—能力提升—玩法验证—新资源回流”的循环。
5. 体验记录只有转化为假设、证据、问题和改进方案，才会成为可执行的策划输入。

## 整理原则

- 仅保留方法论和脱敏后的设计结论。
- 不上传原始 PDF、Word 和独立游戏截图；`xmind/` 目录中的思维导图作为学习源文件单独归档。
- 文中的数值示例用于解释结构，不代表最终平衡配置。
- 对体验结论区分“观察事实”和“个人推断”，避免把单次体验当成普遍规律。

## XMind 源文件说明

仓库的 `xmind/` 目录保存了与学习笔记对应的原始思维导图。GitHub 通常不能直接预览 `.xmind`，需要下载后使用 XMind 打开。文件中包含用于分析的游戏界面截图，仅作为个人学习与作品整理记录。
