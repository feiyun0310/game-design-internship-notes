# 游戏策划实习学习笔记

> 围绕系统策划、交互规格、信息层级和体验复盘整理的个人作品集式学习档案。

## Portfolio Summary

This repository presents my structured study of game-system design during an internship period. It turns observations and mind maps into reusable design methods covering world-map information hierarchy, interaction states, troop deployment, hero progression, data modeling, playtest analysis, and economy-oriented iteration.

## 作品集定位

这个仓库重点展示的不是某一款游戏的数值或界面复刻，而是我如何把体验观察转化为可讨论、可实现、可验证的策划方案：

- 从玩家目标和使用场景识别真实问题；
- 用信息层级、状态机和数据模型拆解复杂系统；
- 将 View 层表现、操作反馈和 Model 层规则分别描述；
- 通过体验记录、对比分析和检查清单推动迭代；
- 在方案中明确异常状态、边界条件和研发协作所需信息。

## 代表性案例

### 1. 大地图：缩放不是等比例放大

大地图在不同缩放层级承担不同任务。近景强调可交互对象和即时状态，远景强调势力、区域与战略关系。因此优化的核心是重新组织信息，而不是只改变模型大小。相关文档明确比较了联盟要塞、建筑归属、保护状态等信息在各层级中的展示优先级。

### 2. 选兵出战：让操作形成闭环

编队界面需要同时回答“当前选了谁、为什么不能继续、调整后发生了什么”。方案从入口、选择、替换、限制提示、确认和返回等状态出发，关注玩家是否能预测操作结果，而不仅是按钮布局。

### 3. 英雄系统：区分 View 与 Model

View 层负责信息如何被理解和操作，Model 层负责英雄、属性、技能、培养资源和规则之间的关系。分层后，界面改版不会隐式改变数值规则，系统扩展也能更早发现数据结构和状态依赖。

### 4. 体验复盘：从感受转化为证据

体验记录按照“现象—原因假设—影响—验证方式—改进建议”整理，并结合资源产出、成长消耗和反馈节奏观察循环问题。这样可以把主观感受转化为可讨论的产品判断。

## 核心设计认识

1. UI 规格不能只画静态页面，还要说明出现时机、可操作状态、成功反馈和失败反馈。
2. 复杂系统应先定义实体、状态、规则和数据关系，再决定页面如何展示。
3. 大地图缩放本质是信息层级切换，需要控制密度、辨识度和决策价值。
4. 成长系统要形成目标、行动、消耗、反馈和下一目标的循环。
5. 体验报告的价值不在于罗列感受，而在于提供假设、证据、影响范围和验证方法。

## 可继续完善的方向

- 为重点方案补充低保真线框图、交互原型和状态流转图。
- 为优化建议定义可观察指标，例如任务完成率、操作耗时、误触率和关键入口点击率。
- 补充策划案版本记录、评审意见与迭代前后对比。
- 将规则模型进一步转成字段表、配置示例和客户端/服务端职责说明。
